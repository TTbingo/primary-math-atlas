# 旧篇目关联知识点的三类化改造规范

## 背景

站内 136 篇旧篇目的 `sections.related` 是旧格式（只有 `{id, note}`），
本轮新增的 26 篇已用三类格式（`{id, kind, note}`）。
本轮要把旧篇目也统一成三类，并保证每类至少一条。

## 三类判据（与新篇目完全一致）

| kind | 判据 | 硬约束 |
|---|---|---|
| 前置 | 学本文之前必须先会的概念/技能 | 目标篇目**必须排在本文之前**（顺序见 `content/modules.json`：依次遍历 `topics` 数组，展开每个的 `points`） |
| 后续 | 学完本文之后，接着会用本文成果的内容 | 目标篇目**必须排在本文之后** |
| 常一起考 | 中考/小升初里常与本文出现在同一道题里的 | 位置不限；多为跨领域对照或同一情境的不同角度 |

每篇 `related` 保持 **2~4 条**，三类齐全。

## 已有 note 的处理

旧篇目的 note 已经带前缀（`前置：`、`进阶：`、`后续：`、`应用：`、`对照：`…共 50 多种）。
**前缀只是线索，不是判据**——判据是位置 + 真实知识关系。

改造时：
- note 保留原有的说明文字，但**去掉开头的类别前缀**（如 `前置：xxx` → `xxx`），
  因为类别已经由 kind 字段承载，渲染层会自动加标签。
- 位置与前缀矛盾的（22 处），以**位置和真实关系**为准，并顺手把 note 改写得准确。

## 缺类时怎么补

一篇缺「前置」时，从**排在本文之前**且**真实是本文前提**的篇目里选一条。
优先选同一主题内紧邻的前一篇，或紧邻主题的前一篇（按 modules.json 顺序）。

一篇缺「后续」时，从**排在本文之后**且**真实会用到本文成果**的篇目里选一条。

一篇缺「常一起考」时，选**位置不限**但**常在同一道题里出现**的篇目。
常见搭配：
- 数与代数 ↔ 图形与几何（同一题里既要算又要画）
- 图形与几何 ↔ 统计（面积题里的统计表）
- 同一主题内的姊妹篇（面积系列、运算系列）
- 综合与实践里的思维方法篇与它对应的运算篇

**不要为了凑数硬拉关系**——如果实在找不到真实相关的，宁可从另一类里调整：
比如「后续」类的某条其实是跨领域对照，改成「常一起考」，然后补一条真正的后续。

## ext: 前缀

站内没有前置知识可用时，用 `ext:` 前缀引用站外内容（不生成链接）：
```json
{"id": "ext:小学没学过负数的乘法，这里只用它表示相反方向", "kind": "前置", "note": "..."}
```
`ext:` 条目不生成链接，但仍然算作对应类别的一条。

## 反向补链

构建器会自动补反向链接（A 的「后续」= B 的「前置」），**不要**在两篇里重复写同一对关系——
只在一篇里写，反向会自动出现在另一页。

## 验证

改完必须全站校验通过：
```bash
cd "D:/workbuddy的工作空间/2026-11-03-11-08-31/math-site"
MATH_NO_CLEAN=1 CODEBUDDY_SAFE_DELETE_ENABLED=0 python build.py --check 2>&1 | tail -20
```

校验器会拦：
- kind 不合法
- 「前置」指向排在本文之后的篇目
- 「后续」指向排在本文之前的篇目
- 三类缺某一类
- 关联 id 不在清单内
